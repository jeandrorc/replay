## Plan

- [ ] Define application-owned ports for review decisions and local settings.
- [ ] Add append-only decision and validated settings schemas through a
      migration.
- [ ] Persist manual activity revisions without changing observed events.
- [ ] Persist capture, timezone, day-boundary, and retention settings.
- [ ] Make multi-step decision writes transactional and atomic.
- [ ] Map corrupt stored values to actionable adapter diagnostics.
- [ ] Add shared contracts and real SQLite integration tests.
- [ ] Run focused and repository-wide harness checks.

## Architectural frame

- Owning layers: application ports and storage adapters.
- Inward-facing ports: review-decision repository and settings repository.
- External adapter: SQLite through the existing connection boundary.
- Invariants: observed facts remain immutable, revisions retain provenance,
  settings are validated at the boundary, and partial decisions never persist.
