# Epic 01 — Domain and capture

## Goal

Define the smallest stable business model and application contracts for evidence
capture.

## Stories

### [~] DOM-001 — Model time ranges and identifiers

Acceptance criteria:

- UTC instants and half-open time ranges reject invalid values.
- Identifier creation is supplied through a port, not generated by the domain.
- Tests cover zero/negative ranges, midnight, DST display boundaries, and
  equality.

### [ ] DOM-002 — Model versioned activity events

Acceptance criteria:

- The event envelope defined by the architecture is represented with validated
  discriminated types.
- Initial kinds cover active application, Git context, idle/resume, capture
  pause/resume, and manual activity without storing prohibited content.
- Unknown persisted event kinds can be retained as opaque evidence.
- Events are immutable after construction.

### [ ] APP-001 — Record a captured event

Acceptance criteria:

- A use case validates collector input, supplies ID/recorded time, and saves
  through a repository port.
- Duplicate observation IDs are idempotent.
- Repository errors become actionable application errors without leaking
  sensitive payloads.

### [ ] APP-002 — Add and edit manual activity

Acceptance criteria:

- A user can create a completed time range or start/stop an ongoing manual
  activity.
- Title is required; category and ticket reference are optional.
- Overlap is allowed but surfaced to review rather than silently merged.
- Editing creates a traceable user decision and preserves original evidence.
